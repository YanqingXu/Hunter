# 接入目标项目

只做技能编辑和表现预览时，不需要接入正式战斗。以下用于需要在游戏运行时执行同一份 SkillClip 的项目。

## 最小接入关系

- `ISkillActor`：提供模型根节点和攻击数值；不要求继承某个角色基类。
- `ISkillHitTarget`：接收 `SkillHitData`，由项目决定如何扣血、击退、播放受击表现。
- `ISkillTeam`：可选阵营接口。技能配置为“敌方/友方”时，施法者和目标都必须实现它；未知阵营不会被猜测为敌人。
- `ISkillAnimationDriver`：可以使用包内的 `SkillAnimationPlayer`，也可以接入项目自己的动画系统。
- `ISkillAudioService`：默认使用 Unity AudioSource；可以把自己的音频服务赋给 `SkillPlayer.AudioService`。返回的 IDisposable 必须只释放本次播放，不得停止其他技能的声音。
- `SkillBehaviourBase`：接收自定义事件、命中和技能结束等回调。Buff、冷却、消耗、UI、状态转换写在项目派生行为中。

如果项目使用自己的 asmdef，在需要执行技能的程序集上添加对 `SkillEditorKit.Runtime` 的引用；正式运行程序集不要引用 `SkillEditorKit.Editor`。

## 一个最小角色示例

下例仅展示连接方式，不提供血量、Buff 或输入系统。把它放在目标项目自己的脚本目录，在游戏运行时由现有输入/AI 调用 `Play()`。

```csharp
using UnityEngine;
using SkillEditorKit;

[RequireComponent(typeof(SkillEditorKit.SkillPlayer))]
[RequireComponent(typeof(SkillAnimationPlayer), typeof(Animator))]
public sealed class MyProjectSkillActor : MonoBehaviour, ISkillActor, ISkillTeam
{
    public SkillEditorKit.SkillClip skill;
    public float baseAttack = 10;
    public int team = 1;
    private SkillEditorKit.SkillPlayer player;

    public Transform ModelTransform => transform;
    public int SkillTeamId => team;
    public float GetAttackValue(SkillAttackDetectionEvent data)
        => baseAttack * (data.AttackHitConfig?.AttackMultiply ?? 1);

    private void Awake()
    {
        player = GetComponent<SkillEditorKit.SkillPlayer>();
        var animation = GetComponent<SkillAnimationPlayer>();
        animation.Init();
        player.Init(this, animation, ModelTransform);
        player.StartPlaySkillBehaviour(new SkillBehaviourBase
        {
            CustomEvent = data => Debug.Log("项目处理技能事件：" + data.CustomEventName)
        });
    }

    public void Play()
    {
        if (!Application.isPlaying || skill == null) return;
        // 在这里先检查并结算项目自己的冷却、资源消耗和释放条件。
        player.PlaySkillClip(skill);
    }

    public void BeHit(SkillHitData hit)
    {
        // 接到项目自己的受击/血量系统，不要在编辑器里扣血。
        Debug.Log(name + " 收到攻击：" + hit.attackValue);
    }
}
```

还需要在 SkillPlayer 上设置攻击检测层，并在目标上添加 3D Collider 与实现 `ISkillHitTarget` 的组件。敌我筛选使用双方 `ISkillTeam` 的数值，不依赖任何固定层名称；层掩码和碰撞设置由目标项目决定。

对于追踪投射物/目标朝向/指定落点，释放前使用 `player.SetAimContext(targetTransform, worldPoint)`。普通前方技能可以不指定目标。

## 项目行为扩展

派生 `SkillBehaviourBase` 即可覆盖 `AfterSkillCustomEvent`、`OnHitTarget`、`OnProjectileHitTarget`、`OnRootMotion`、`OnSkillClipEnd` 等回调。

- 内核会执行时间表、筛选、去重和投射物规则。
- 默认命中回调调用目标 `BeHit`，并提供基础 Unity 音效/特效反馈。需要自定义反馈时覆盖命中回调。
- 默认 Root Motion 回调不直接移动角色；应在项目行为中将位移交给自己的移动控制器。
- 默认行为不扣资源、不运行冷却、不添加 Buff，也不更新 UI。
- 每个同时执行的角色使用独立的行为实例。不要把同一个正在运行的行为绑定给多个播放器。
- 动画驱动应当属于一个角色；音频租约和技能资源按单次执行管理。更换音频服务不会改写已经开始的那次技能的服务引用。

不使用内置动画组件时，实现 `ISkillAnimationDriver` 的采样回调。技能内核传入的是技能时钟推进量，暂停、取消和跨帧推进应遵循这个时钟，避免同时用另一套自动播放时钟推进同一段动画。

## 与原工程并存

独立版没有修改原工程的 `Skill_Player`、`SkillBehaviourBase`、角色接口或已有资源。导入后原系统仍走原来的业务逻辑，新系统使用 `SkillEditorKit` 类型。需要让原工程也改用新内核时，应单独迁移项目接入层和资源引用，不能直接批量替换同名脚本。
