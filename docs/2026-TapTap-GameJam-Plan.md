## 3. 参赛范围与角色职责

### 3.1 参赛包最小范围

| 必须完成 | 控制规模 |
| --- | --- |
| 主题表达 | 开题后选一个与核心操作直接相关的主题机制，玩家可在前 2 分钟感知 |
| 操作与战斗 | 跑、跳、瞄准、射击、换弹、受击、死亡；一把枪 |
| 地图 | 一张小型固定地图，少量分支，一种普通怪，一个 Boss |
| 风险与撤离 | 拾取战利品，选择继续冒险或撤离；失败与成功结果清晰 |
| 最小结果与存档 | 当局成功/失败、带出数量、累计记录；本地结算不重复应用 |
| 本机运行 | Unity 自动管理随包服务端；回环连接、启动握手、版本校验、异常提示与退出清理 |
| 基本可用性 | 标题、开始、操作提示、暂停/音量、结算、重开、退出 |
| 发布产物 | 可运行安装/压缩包、说明、页面素材、演示与实机视频、素材来源记录 |

比赛期不排入：跨设备联机 PvP、匹配、在线账号系统、云存档、远程数据库、完整永久猎人资产经济、复杂特质、转生、自由地形破坏、双端适配。这里的本地存档可靠性不等同于赛后远程服务端的资产防篡改能力；本地权威用于保持规则和状态归属一致，不承诺防止玩家修改本机程序或存档。

可选项仅在 10/12 之前、所有必做项已验收且至少有 1 天余量时考虑：一个补给道具、Boss 第二种攻击、简单环境反馈。任何可选项不延迟首次上传。

### 3.3 本机架构与发布形态

```text
玩家启动 Unity 游戏
  ├─ 自动启动随包 C++ 服务端，等待就绪并校验版本
  ├─ 127.0.0.1 / TCP / Protobuf → 输入、交互、暂停、结果查询
  └─ 127.0.0.1 / TCP / Protobuf ← 权威快照、事件、已提交结果
                       C++ 服务端
                         ├─ 固定 Tick：运动、战斗、AI、撤离
                         └─ 本地持久化：结果、去重记录、存档

design/ 源表 ＋ 地图数据
  → export/ 校验与导出
  → 客户端资源/表现配置 ＋ 服务端规则/碰撞数据
```

- 比赛包采用一个 Unity 客户端进程＋一个本地服务端进程。复用已有代码时，将需要的职责组合到本地宿主，不要求玩家手动启动 Gate/World/Game/DBProxy 或安装数据库服务。
- 服务端只绑定 `127.0.0.1`；比赛包不提供远程地址输入、局域网发现、外网登录或运行时下载。代码和依赖的真实外部访问情况在打包验收时检查。
- 首版使用本地 TCP 消息通道，约定长度分帧、消息大小上限与错误处理；不同时建设 UDP/KCP、复杂弱网恢复和历史命中补偿。服务端 Tick 独立于收包与渲染推进。
- 本机版本先实现及时的输入发送、权威状态展示和必要平滑；仅在操作验收表明需要时增加小范围预测校正，完整远程预测方案留待赛后。
- 本地存档由服务端单一写入，客户端只显示已确认结果；采用无需额外安装服务的嵌入式存储或安全文件写入方式，10/1 选定，10/7 验证重复提交与重启。
- 服务端故障时客户端停止继续演算奖励，显示原因并返回入口；首版不承诺恢复未完成对局。下一次启动读取最后已确认结果，对未决局不重复发奖。该失败体验由策划在 10/1 明确。

| 契约/产物 | 主责与评审 | 首版截止 | 验收方式 |
| --- | --- | --- | --- |
| 启动与生命周期 | C 主责进程管理；S 提供命令行、就绪、退出接口 | 10/1 契约，10/2 可自动启动 | 端口由服务端绑定后交付，避免固定端口冲突；等待就绪超时可诊断；不盲连其他进程 |

最小消息族为：版本/内容握手、开局、输入序号与动作、权威快照与事件、交互、暂停/继续、结算结果查询、健康/关闭。每个消息约定关联 ID、错误返回与重试行为；不引入匹配、账号注册和远程重连业务。玩法消息在 10/6 完成首版，10/12 后协议原则上冻结。

### 3.5 生命周期专项验收

客户端负责启动失败提示、等待就绪、连接中断、退出清理；服务端负责明确就绪信号、只监听回环、存档写入完成后退出，以及客户端消失后的有界退出。C/S 约定只管理本次启动的子进程，不能按进程名清理其他游戏实例。

10/4 检查正常启动/退出与端口冲突；10/10 检查服务端崩溃、客户端强退、多开策略和存档占用；10/14 用普通用户权限在干净 PC 断网重测。包内提供必要运行依赖，不要求管理员权限或手工开终端。发生错误时给出重试/返回入口与可定位日志，不无限等待。

## 7. 每日协作与检查方式

- 每人开始工作前用 10 分钟同步当天交付与阻塞；跨角色接口问题当天解决，不等周会。
- 按每人约 5 小时安排：约 3 小时主任务、1 小时集成/修复、30 分钟试玩、30 分钟记录与沟通。每日同步包含在沟通时段内。
- 20:30 前合入当日可用改动；21:00 出包；21:30 全员玩同一版本并记录结果。无法符合该时段时，9/22 一次性对齐全队固定交集。
- 主分支每日可构建。未完成任务保留在各自分支，不让占位功能阻塞其他成员的可玩版本。
- 10/4 起每日保留版本号、提交、配置版本、可玩包位置和已知问题；10/12 后每个修复附复现步骤与回归结果。
- 每张任务卡写负责人、前置依赖、目录、完成条件和预计小时；超过 1 天的任务拆成能演示的子任务。

最低检查集：断网一键启动双进程；普通用户权限；端口冲突；版本/地图/配置不符；新玩家完成一局；死亡/撤离重开；重复输入与结算；暂停时服务端停止计时；客户端/服务端分别强退；下一次启动读取最后已确认结果；损坏/不可写存档；退出不留子进程；不依赖开发机路径；连续 10 局和 10 次启停无阻塞。性能目标和测试设备在 10/4 前记录。
