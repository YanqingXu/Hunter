# Hunter 配置表填写说明

> 状态：Excel 配置模板与示例已支持导出服务端 Lua，待游戏逻辑接入。策划在 `export/导出目标.txt` 中每行填写一个 Excel 文件名，保存后双击 `export/导出配置.exe` 即可导出，不需要安装 Python。当前构建仍只读取 `combat_demo.json`；修改 Excel 并导出暂时不会改变游戏。客户端导出尚未实现。

这套源表面向策划填数值、客户端接表现、服务端接规则。共 7 个 Excel、15 张数据工作表、103 条配置记录，覆盖单人 PvE 撤离 Demo。包含原灰盒、撤离示例和废弃工厂三张地图；新增数值作为首轮调参基线，尚未经过玩法平衡或实机验收。

## 2. 统一填写规则

### 表头与导出范围

| 行 | 含义 | 示例 |
| --- | --- | --- |
| 1 | 中文字段说明，含必要单位 | 撤离读条（Tick） |
| 2 | 数据类型 | `int32`、`string` |
| 3 | 程序字段名，大小写固定 | `HoldTicks` |
| 4 | 导出端与键标记 | `server/client/key` |
| 5 起 | 一行一条数据 | 不插入额外标题行或小计行 |

- `server/client` 与 `client/server` 等价；`key` 是主键，`index` 是原表保留的普通检索标记，不取代主键，也不声明名称唯一。规则字段供两端使用，图标、场景、动画、音效等表现字段仅供客户端。
- 每张表从 A 列开始连续声明字段。最右侧隔一空列的“待接入”提示没有类型、字段名和导出标记，不属于数据区。导表工具按连续的第三行字段确定读取范围，不会把已使用区域全部导出。
- 已冻结前四行和 A 列。数值与枚举输入校验覆盖第 5～504 行；超出时复制上一行的格式与校验。Excel 粘贴可绕过校验，且跨文件引用不由下拉框校验，提交前仍需按第 8 节核对。
- 不合并数据单元格，不在数据区插入空列。多条出生、技能、掉落分别填写多行，不使用逗号列表、JSON、公式或脚本字符串。完全空白的数据行可忽略；存在主键的行必须补齐必填字段。

### 类型、单位与空值

- 主键及所有 ID 引用均声明为 `int32`。主键范围 1～2147483647，每张表独立编号，不能依据行号、名称、ID 数字位推断属性。运行时实体 ID 与配置 ID、出生 ID 相互独立。
- 新填 ID 使用整数单元格。原道具 `ItemIdx=3` 仍保留原先的文本存储形式，导表工具严格解析为整数 3；不能把它与数字 3 当成两个 ID。
- 必填数值不得留空。可选引用也必须填数字，`0` 表示不关联；未填写与 0 不同。原有四条货币的 `Item.Type` 历史空值已补为 `0`（未细分），现在所有行统一必填。导表不会自动补零。
- 距离、位置、体型为整数毫米；速度为毫米/Tick，重力为每 Tick 的速度增量，即毫米/Tick²。时间为整数 Tick，固定 60 Hz：60 Tick=1 秒，90 Tick=1.5 秒，180 Tick=3 秒。
- X 向右、Y 向上。玩家/怪物出生为脚底中心，碰撞块与撤离区为左下角加宽高。角色宽高必须为偶数，保持半宽为整数。
- 新的资源字段暂留空，表示资源待交付，不是有效的美术路径。原道具图标字符串照原表保留，本轮不声称资源文件已存在。

### ID 与保留枚举

- 道具 ID 继续使用原批注中的分类区间；示例装备 `100000001`、杂物 `2800001/2800002` 均在对应区间内。废止与九位装备区间矛盾的十位编码示例，新增装备不按位编码职业、等级、品质或武器类型。
- 保留原大类的全部数值；本轮使用 `Kind=1` 装备、`Kind=4` 普通道具、`Kind=10` 值类型货币。原宠物、时装、生活技能等枚举只是预留分类，不表示相关系统纳入本轮。原大类/小类批注继续保留。
- 装备位置保留有效值 1～11，详见字段字典。原批注中以横线标出的 12/13 为历史记录，当前不采用。
- 武器类型保留 1=剑、2=刀、3=杖、4=扇、5=手套、6=爪，新增 7=枪械，0=非武器。首版武器行为仅为射线枪械，其余武器类型保留枚举，不宣称已实现。
- 装备示例使用 `Kind=1 / Type=1 / SubType=7`，分别表示装备、武器、枪械。`EquipPos=1 / WeaponType=7` 与之对应；不要把其他道具大类的 Type 解释为装备位置。

## 3. 跨表关系与规则

```text
Map ← MapSolid / PlayerSpawn / MonsterSpawn / ExtractPoint
PlayerSpawn → Player；PlayerSpawn.EquipItemIdx → Equip.ItemIdx → Item.ItemIdx
Equip.WeaponIdx → Weapon.AttackSkillIdx → Skill
PlayerSkill → Player + Skill
MonsterSpawn → Monster；MonsterSkill → Monster + Skill
Monster.DropIdx → Drop ← DropEntry → Item
ExtractPoint.NeedBossSpawnIdx → 同地图的 MonsterSpawn → Rank=2 的 Monster
```

### 地图与出生

- `MapIdx=1` 保留原灰盒：24×10 米、三块实心矩形、一个玩家和两名普通怪，不配置撤离点。`MapIdx=2` 为独立撤离示例，几何相同，关联示例玩家、普通怪、Boss 与撤离点。`MapIdx=3` 为 36×12 米废弃工厂，配置五个敌人出生和两个撤离点。
- 每张地图首版恰好一个玩家出生、1～32 个怪物出生、最多 128 个实心矩形。出生不能越界、穿透实心块、悬空或与其他出生角色重叠。实心块彼此不能重叠。巡逻扫掠区域计入怪物半宽，必须有连续地面/平台支撑，不能穿墙。
- 每个出生点只生成一次。示例不配置重生和刷怪波次；因此撤离条件可准确指向某个 Boss 出生实例。地图、障碍、玩家出生、怪物出生分别使用独立 ID 空间。

### 技能与枪械

- 伤害、攻击距离与冷却仅由 Skill 维护。Weapon 只维护弹匣、初始备弹、换弹以及攻击技能引用；Monster 维护警戒与基础属性，不重复保存攻击数值。
- `CastType=1` 是射线直接伤害，保留现有最近命中与墙体遮挡语义；`CastType=2` 是近战单次伤害，保留横向距离、竖直相交、视线不被墙阻挡的条件。全部示例只攻击敌方。
- 冷却从施放开始计时；前摇结束时重新判断目标能否命中，命中尝试仅一次，然后进入后摇。未命中也消耗此次冷却。前摇+后摇不得超过冷却；施法者死亡取消未完成招式，暂停冻结所有计时。射线示例前后摇均为 0。
- 玩家技能表配置额外主动技能，不绕过枪械弹药规则。玩家 1 无额外技能；玩家 2 的槽 1/2 分别绑定 Skill 2/4；玩家 3 的槽 1 绑定 Skill 5。上述近战技能也被怪物引用。武器攻击仍只通过 Weapon.AttackSkillIdx 调用。
- 同一玩家的槽位及技能不得重复；同一怪物的技能及优先级不得重复。怪物按优先级从小到大尝试可用技能，原灰盒与撤离示例仍各绑定一个技能，工厂精英与 Boss 各绑定两个。技能冷却独立计时，同一单位前摇和后摇期间不并行施放其他技能。怪物警戒范围不得小于其近战技能距离。
- 新玩家近战、Boss 前后摇和技能优先级属于配置约定，当前程序未接入；已有普通怪/枪械仅用它们做原数值的字段映射。

### 掉落与撤离

- 各 DropEntry 独立判定，ChanceBp 是万分比概率而非权重，不要求同组概率之和为 10000。10000 必掉、0 不掉；成功后在整数闭区间 [MinCount, MaxCount] 内等概率取数量。
- 一个掉落组中同一道具只能一行；数量至少为 1，MaxCount ≥ MinCount。固定数量用相等的上下限表示，固定掉落再配 ChanceBp=10000。
- 示例普通怪有 60% 概率掉 1～3 个废铁；Boss 必掉 1 个徽记和 3～5 个废铁。Kind=10 的原货币不占背包格，未纳入本轮掉落示例。其余物品超出 MaxStack 时应拆分堆叠，不能丢弃余数；背包容量和跨局保存另行接入。
- 工厂怪物掉落兽牙、铭牌、零件和晶核；精英有 10% 概率掉冲锋枪，炉心巨兽有 20% 概率掉侦察步枪。所有装备掉落均为 1 件。当前表只描述装备物品，拾取装备时的装填状态与换装行为留待装备系统接入。
- 撤离示例要求地图 2 的怪物出生 14 死亡后开放，玩家脚底中心进入 [X,X+W]×[Y,Y+H] 的闭区间开始累计；NeedBossSpawnIdx=0 则不要求 Boss 条件。
- 读条使用每行 HoldTicks；撤离示例与工厂首领出口为 180 Tick，工厂提前出口为 120 Tick。离开区域、受到正伤害或死亡会清零；暂停冻结计时；死亡时不能完成撤离。重开对局后 Boss 条件及读条重置。首版 Mode=2 至少配置一个撤离点，Mode=1 不配置撤离点。
- 表中只定义撤离资格和读条，不保存当前拾取归属、Boss 存活状态、结算提交结果或背包实例。死亡损失、持久化事务及幂等结算需在玩法接入阶段单独实现。

## 7. 常用修改步骤

### 新增地图

1. 在 Map 添加未占用 MapIdx、模式、尺寸、重力和已交付的场景资源引用。
2. 在 MapSolid 按左下角/宽高添加矩形，使用本表未占用 SolidIdx，并关联新地图。
3. 在 PlayerSpawn 添加唯一玩家出生，引用已有 Player 和 Equip；核对装备能解析到 Weapon 与 Skill。
4. 在 MonsterSpawn 添加怪物与巡逻区，用实际体型检查支撑、边界及重叠。
5. 撤离地图至少添加一个 ExtractPoint；指定 Boss 时引用新地图中的出生 ID，而不是 MonsterIdx。

### 新增怪物或 Boss

1. 在 Monster 填基础属性、Rank、表现资源和可选 DropIdx，避免复制伤害/攻击距离列。
2. 复用或新增 Skill，通过 MonsterSkill 绑定；同怪物的 Priority 和 SkillIdx 分别唯一。
3. 在 MonsterSpawn 放置实例。Boss 用 Rank=2，并在撤离点绑定具体 SpawnIdx。

### 新增技能或武器

1. 先在 Skill 填施放类型、攻击距离、伤害和 Tick 时序；0 前后摇可复现当前灰盒攻击。
2. 玩家额外技能添加 PlayerSkill 的独立槽位；怪物招式添加 MonsterSkill；同一 Skill 可以被多种使用者引用。
3. 枪械攻击在 Weapon 填 AttackSkillIdx、弹匣、初始备弹和换弹，不重复加入 PlayerSkill。
4. 在 Item 与 Equip 新增相同 ItemIdx 的装备记录，EquipPos=1、WeaponType=7 并引用 Weapon；在 PlayerSpawn 选择该 EquipItemIdx。

### 新增掉落

1. 道具先进入 Item；普通战利品使用 Kind=4，设置说明、图标和正堆叠上限。
2. 新增或复用 Drop，按物品逐行添加 DropEntry；同组同物品不能重复。
3. 必掉固定数量填写 ChanceBp=10000 且 MinCount=MaxCount；概率和数量均不要写百分号字符串。
4. 在 Monster.DropIdx 引用掉落组，检查所有 ItemIdx 存在。

## 9. 后续接入边界

目前已交付源表、说明、`export/导出配置.exe` 策划入口与 `export/export.py` 服务端导表工具。策划修改 EXE 旁边的 `导出目标.txt`，每行填写一个 Excel 文件名（例如 `道具表.xlsx`），然后双击 EXE。每个选中文件中的所有服务端工作表都会导出，未选文件的旧输出保留；有跨表联动修改时请把相关文件一起写入清单。

工具递归查找 Excel，忽略 `~$` 开头的 Office 临时文件，根据四行表头校验并生成 `server` 列，一张表对应一个以数字主键索引的 Lua 文件。输出到 `server/build/generated/cfg`，结果窗口可直接打开输出目录，日志位于 `export/导出结果.log`。开发也可执行 `py -3 export/export.py` 导出全部文件，或加 `--check` 只校验且不写文件。完整命令、支持类型、错误处理及测试见[导表工具说明](../export/README.md)。

新增符合约定的工作表即可参与导出，无需在代码中登记。所有数字字段（含可选引用）必须明确填值，公式和错误值拒绝导出；空字符串输出为 `""`。批量导出在全部校验通过后才发布文件。删除或重命名表后的旧 Lua 不会自动删除，需手动清理。

客户端输出、游戏端加载、跨表业务校验及同局内容版本将在接入阶段补充。生成文件直接 `return` 数据表，不能直接作为现有 `factory(deps)` 脚本模块加入模块清单。

现有 `export/combat.py` 只接受精确的 combat-v2 JSON 字段，不能直接把新表或新字段塞入它。原灰盒可按第 5 节投影做兼容验证；完整多地图、主动技能、掉落和撤离需独立的内容版本与加载契约。切换时再明确 Excel 为唯一源、JSON 为生成物，避免人工双写。当前 `combat_demo.json` 继续作为运行时唯一来源。
