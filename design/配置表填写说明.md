## 工作表格式、类型与单位

工作表名使用 `中文名|EnglishName`，英文名成为 Lua 表名，整个根目录不允许大小写意义上
重复。无 `|` 的说明工作表、`~$` 开头的 Excel 临时文件、子目录归档不进入正式扫描。
`Tables` 和 `Fixture` 为内部保留表名。含导出格式的客户端工作表会检查表头，但只导出
带 `server` 标记的字段和表。

| 行 | 填写内容 | 示例 |
| --- | --- | --- |
| 1 | 中文字段说明 | 单次补给数量 |
| 2 | 字段类型；服务端只支持 `int32`、`string` | `int32` |
| 3 | 唯一英文字段名；沿用现有拼写 | `RefillCount` |
| 4 | 以 `/` 分隔的 `server/client/key/index` 标记 | `server`；主键为 `server/key` |
| 5 起 | 数据记录 | `5` |

每表必须有且只有一个服务端 `int32` 主键，范围为 1～2147483647，不能重名。整数不得留空，
不能用空格或公式代替明确数值；文本字段须为文本单元格，允许空串。公式和 Excel 错误值
不参与计算，会阻止导出。主键为以 `#` 开头的文本时，该行作为说明忽略。

有序 ID 列表按文本填写，如 `12|13`；空串或文本 `0` 仅在允许无引用的字段表示关闭或为空。
其他列表不得包含空项、重复引用或 `01` 等非规范整数。价格为文本 `0` 或
`货币ID:正整数数量`，例如 `2800001:10`；不能把数字单元格当作价格文本。

坐标、尺寸和距离使用整数毫米；脚底中心为角色位置，X 向右、Y 向上。速度为毫米／Tick，
计时字段为 Tick，固定模拟为 60 Hz；`120` Tick 为 2 秒。`Bp` 和 `mul_bp` 使用万分比，
`10000` 表示 100%；`ToolMovePercent/SlowPercent` 使用整数百分比，不混用万分比。

Python 负责全量读取和类型检查，Lua 负责关联、单位、几何、数值范围及可执行机制门禁。
读到所有记录不等于启用所有内容。禁用记录仍需填完整字段，不可借 `Enabled=0` 隐藏非法
引用；地图子记录由服务器选择后进入当前运行内容，其他地图的数据也必须能通过源类型检查。

## 服务器入口、地图与配装

`Server` 必须且只能有 `ServerIdx=1` 一行。`MapIdx/BagIdx/RulesIdx/LoadoutIdx` 是必填正
外键；`CareerIdx/EncounterIdx=0` 明确关闭成长或遭遇，非零时引用对应记录。当前初版选择
地图 2，不将地图或其他规则主键固定在程序中。

`Map` 定义宽高、重力，当前所选地图须为撤离模式 `Mode=2`。`MapSolid/PlayerSpawn/
MonsterSpawn/ExtractPoint/Scene/Region/ItemSpawn` 通过 `MapIdx` 归属地图。
所选地图恰好一个玩家出生点，出生玩家和首把武器须与 `Loadout` 一致；角色、怪物和物品点
不能在实心碰撞体内部。怪物巡逻范围、场景及出口几何均需位于地图范围内。

`Loadout.Weapons/Ammo` 按槽位一一对应，`Tools/Consumables/Skills` 用 ID 列表明确配置。
`Rules` 定义武器、工具、消耗品槽位、场景与投射物容量、工具读条移动限制和枪械近战耗体。
`Bag` 定义战利品格数及拾取距离。`PlayerSpawn.EquipItemIdx` 引用 `Equip` 的枪械物品，
`Equip.WeaponIdx` 再引用 `Weapon`，不要直接填武器 ID 代替物品 ID。

当前撤离出口自由开放；赏金拾取后标记全部出口并触发遭遇规则。历史夹具中的
`NeedBossSpawnIdx` 清 Boss 开门规则不代表正式出口自动受该字段封锁。

## 弹药与工具补给

| 来源字段 | 含义与填写要求 |
| --- | --- |
| `Weapon.Magazine/InitialReserve` | 弹匣与初始备弹；有效技能可修改备弹容量。单枪弹匣加备弹容量不得超过 100000。 |
| `Weapon.DefaultBullet/BulletType` | 当前均引用同一 `Ammunition` 默认弹药。 |
| `Weapon.ReloadType` | `1` 整匣，`2` 逐发；`Interval/ReloadTicks` 为正 Tick。 |
| `Ammunition.Bullet/Bamage/Biffusion` | 弹丸数、子弹伤害、散射角。后两个字段沿用源表历史拼写，不能自行改名。 |
| `Ammunition.RefillCount` | 该弹种每次补给数量，非负整数；当前初版弹药 1/2/3 为 5/3/6。 |
| `Ammunition.Penetration` | 子弹可穿透指定场景道具的数量，命中怪物不消耗该数量。 |
| `Ammunition.Prop` | 允许穿透的 `Scene` ID 文本集合，如 `3` 或 `3|7`；空串／`0` 表示没有。只能引用 `cover`。 |
| `Ammunition.Weaken` | 每穿透一个掩体后固定扣减的子弹伤害。 |
| `Ammunition.PropDamage` | 对场景道具造成的伤害，当前用于扣减炸药桶生命；与穿透扣减分别配置。 |
| `Tool.Quantity` | 当前工具初始次数及基础上限。 |
| `Tool.RefillCount` | 常规工具一次补量，非负整数；医疗包初版为 1。 |
| `Tool.SupplyWeight` | 消耗品补给候选权重，非负整数；正权重才进入抽选。 |
| `Tool.Enabled` | 必填 `0/1`；未实现工具保持 0。 |

弹药补给场景填写 `Scene.Kind=ammo_supply`。容量按同种已装备枪械的有效弹匣与备弹上限
求和，持有总量按弹匣加备弹计数；一次按该弹种 `RefillCount` 补入备弹，按稳定槽位分配，
不直接填满弹匣。所有已装备弹种都满时拒绝交互。此规则按枪械统计，没有新增共享弹池。

实际穿透同时要求场景 `Penetrable=1`、弹药允许该场景 ID、子弹仍有穿透数量；列表中引用
`Penetrable=0` 的掩体仍会挡弹。全局弹药表的场景引用按当前地图投影。

工具补给场景仍为 `Scene.Kind=supply`。先在缺次数且 `RefillCount>0` 的已装备常规工具中
随机选一个补充；常规工具全部满后，再按 `SupplyWeight` 抽取一个消耗品。容量不足、没有
合法候选或全部弹药已满的拒绝不会消费场景；数量与场景状态一次提交，重复请求不得重复发放。

当前支持常规匕首、医疗包及消耗品生命针剂、炸药。荧光棒和持续恢复针剂尚未接入，保持
`Enabled=0`。`Item.Kind=4` 对应工具，`Tool` 主键直接使用工具物品 ID。

## 掉落与随机物品点

`Monster.DropIdx` 引用 `Drop`，`0` 明确无掉落；`DropEntry` 通过 `DropIdx` 给出物品、
`ChanceBp` 和 `MinCount/MaxCount`。概率范围 0～10000，数量为正且最大值不小于最小值。
当前初版普通战利品和 Boss 赏金分别使用掉落组 1/2。

`ItemSpawn` 定义地图、位置、刷新概率 `ChanceBp` 和 `PoolIdx`，`SpawnPoolEntry` 以
`PoolIdx` 归组，定义 `ItemIdx/Weight/Count`。权重必须正数，每个引用池至少有一个候选，
总权重不超过 int32。每点先判断刷新概率，成功后抽一个候选。

技能物品使用 `Item.SkillIdx` 引用已启用技能，数量必须为 1；其余地面随机来源当前限于
消耗品或撤离战利品，不因 `Item` 中存在普通工具、枪械或货币而自动允许地面刷新。
候选数量不能超过合法堆叠量；随机物品与两波怪物掉落的最坏情况地面实例总量须不超过 64。

## 技能、角色与成长

`Skill` 保存身份、`Target/Category/Lifetime` 和 `Enabled`；描述只用于展示。
`Attribute` 使用 `AttributeId/Stat/Target/Unit/AllowedOps/ValueMode` 定义属性字典，
`SkillEffect.AttributeId` 引用该字典，以 `Op/Value` 定义效果。不要恢复旧 `Stat` 文本直填
或按描述推断效果。`AllowedOps` 按文本填写 `add|mul_bp` 等明确操作。

当前启用技能 1/2/4/5/7/8/9/10/11/12/13；3/6/14/15 保持禁用，分别等待体力规则下的
技能作用、听觉感知、开箱额外奖励及有效携带上限机制。奔跑和跳跃当前不扣体力，仅近战
扣耗；不能为了技能 3 自行开启跑步扣耗。禁用效果仍验证属性对象、运算、单位与数值。

`PlayerSkill` 校验角色、技能外键及角色内槽位唯一性，默认拥有的技能由 `Loadout.Skills`
明确配置。`Player` 的分段生命 `HPSetting` 用正整数列表，段总量须匹配生命上限；
`Cost` 为明确价格。`Career` 定义撤离、赏金及退役经验与赏金货币；`CareerLevel` 等级 ID
从 1 连续排列，累计经验首级为 0、随后严格递增。启用成长时，`KillXp` 覆盖已启用的
非召唤怪物，不能由默认经验替代缺记录。

## 怪物状态、能力、波次与场景

`Monster.Enabled` 必填 `0/1`。`Rank` 为 1 普通、2 精英、3 Boss、4 召唤物，避免沿用旧
草稿的 Boss 编号。基础攻击通过 `AttackIdx` 引用 `Attack.Range/Damage/CooldownTicks/
WindupTicks/RecoveryTicks`，前摇加后摇必须小于冷却。旧 `Ap/Interval/Scope/Skill` 不
代替当前攻击和能力表。

`MonsterAi` 按 `MonsterIdx` 绑定唯一 AI，定义警戒速度、脱战时间、减伤、普攻开关与
`RageThresholds/RageTicks/RageAbilityIdx`。血量阈值按严格递减的正整数列表填写，触发
要求生命严格低于阈值。`Ability.Kind` 当前为 `melee/summon`；召唤引用 Rank 4 且无奖励
的怪物，并配置消失时间。`MonsterAbility` 以 `Phase=alert/rage` 和正 `Priority` 绑定能力。
`MonsterAi.AlertSpeed` 是当前警戒速度来源，不以旧 `TriggerSpeed` 替代。

`Encounter.BountyItemIdx/AlertScaleBp/SecondWave` 定义赏金、全图警戒扩大倍率及第二波
出生点 ID。当前地图 2 的初版 `SecondWave=12|13` 复用首波出生点；拾取赏金后追加新的
实体实例，即使首波同出生点怪物仍存活也不覆盖它。第二波不允许 Boss 或召唤物，连同
两波和召唤的最坏情况怪物容量不超过 63。

`Scene.Kind` 当前支持 `ladder/supply/ammo_supply/cover/clue/barrel`。
`SceneAction` 绑定场景，`Mode=instant` 时 `HoldTicks=0`，`Mode=channel` 时为正 Tick。
`Barrel` 为炸药桶提供生命、引信、范围和伤害；`Region` 按地图定义区域几何、Boss 出生点
和线索关联。更改读条、波次、伤害或成长后仍须执行完整配置校验。

## 改表后的交付

先关闭或保存 Excel，执行正式 `--check`；成功后完整导出并重新组装脚本。客户端派生
`content.json` 为 v6，摘要前缀为 `gameplay-v6:`；Host 契约 v9、上下文／内部状态 v8、
协议 v6、SQLite V2。不要手工改 `generated/` 或复用旧内容摘要。

失败时修复错误提示指向的工作簿、工作表、单元格或 Lua 关联规则，再重导。历史 JSON 仅能
通过显式 `--fixture` 进入隔离测试输出，不能作为生产失败后的回退。实际服务端和打包验证
记录由 [VERIFICATION.md](../server/VERIFICATION.md) 按执行日期维护。
