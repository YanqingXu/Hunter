# 服务端配置 v5

本说明对应 SRV-014。`demo_sources.json` 仍显式选择原 19 张表；新增机制表默认不选入。
新模板没有填入演示数值。填写完整参数并通过生产导出校验后，才能将实际 ID 加入清单。
旧填写说明中的共用攻击 Skill、Rank=2 表示 Boss、PlayerSkill 主动槽是历史设计。

## 原有来源与新增身份

- Player 的生命、血段、移动、恢复、负重继续生效。SkillPoints 是初始可用技能点。
- Player.Cost 必填：`0` 表示免费，`货币ID:正整数数量` 表示招募价格，不接受空值。
- Monster 分类：1普通、2精英、3Boss、4召唤。草稿1–7的不完整记录继续排除。
- 普通攻击仍读取 Monster.AttackIdx → Attack；玩家天赋和怪物能力各自独立。
- Weapon 经 Equip 获得唯一物品身份 item_cfg_id，同武器不能映射多个装备物品。
- 需要技能掉落时，在 Item 增加 SkillIdx 服务端整数列；非技能物品填0，技能物品引用
  已选入 Skill。当前未增加此列的基线物品明确投影为 skill_cfg_id="0"。

## 玩家天赋

技能表补齐 G 列展示字段，新增 Target、Category、Lifetime。SkillType 保留草稿信息，
运行时独立读取生命周期，不从旧枚举推断新规则。

| 字段 | 规则 |
| --- | --- |
| Target | player、weapon、tool |
| Category | numeric 数值、mechanic 机制 |
| Lifetime | passive 常驻、once 消费一次、death 成功复活后移除 |
| Cost | 非负技能点；永久已拥有技能由交易系统核算，不重复扣初始点 |

`技能效果|SkillEffect` 每行填写 EffectIdx、SkillIdx、Stat、Op、Value。选中技能必须至少
有一条完整效果，不能引用未选技能，同技能不重复 Stat。`add` 是固定增量；`mul_bp` 是
基点倍率：10000不变、5000减半、20000翻倍。先加固定增量，再将各倍率相对10000的增量
相加，统一向下取整。有效值越界时拒绝完整配装。
同一种枪械或工具占用多个槽位时，仅计算一次对应配置。医疗读条为1–36000 Tick，
投掷距离最多100000毫米；投射速度最多1000毫米/Tick，与原生状态边界一致。

| 技能 | Stat |
| --- | --- |
| 1 死灵法师 | revive_hp、revive_stamina 均必填绝对整数，Op=add，Lifetime=once |
| 2 重振旗鼓 | revive_full_hp，Op=add、Value=1，Lifetime=death |
| 4 军需官 | weight |
| 5 灵缇 | run_speed |
| 7 枪斗术 | melee_damage |
| 8 弹药大师 | reserve，仅在开局初始化发放，不因重算再加弹 |
| 9 手速超群 | reload_ticks |
| 10 稳定瞄准 | shot_ticks，按确认方案解释为射击间隔，不是切枪时长 |
| 11 妙手回春 | medkit_ticks |
| 12 灵丹妙药 | medkit_heal |
| 13 投球好手 | throw_range |

3、6、14、15 尚不支持。未给数值继续空置，不能据描述补百分比。复活由玩家确认后立即
原地执行；成功后180 Tick抑制新警戒目标，不是无敌。局内选择用 Loadout.skills；
旧 PlayerSkill 保留草稿，不自动转为初始天赋。

## 怪物能力与第二波

新增 MonsterAi、Ability、MonsterAbility。所有选入参数必须填写，明确不用才填0。

- MonsterAi：每怪唯一；AlertSpeed 是警戒/狂暴速度，DisengageTicks 是脱战等待，
  DamageReductionBp 是减伤基点，Basic 为0/1。RageThresholds 是用竖线分隔的严格递减
  绝对生命阈值；不用狂暴时填空字符串、RageTicks=0、RageAbilityIdx=0。
- Ability：Kind=melee 或 summon，前摇+后摇严格小于冷却。melee 伤害正数且召唤ID、消失
  延迟为0；summon 伤害0、引用无掉落rank4怪，必须填写双圈外消失等待。禁止递归召唤。
- MonsterAbility：每怪最多8项，Phase=alert/rage。优先级小值先，同优先级按能力ID。
  同怪物不重复能力ID；狂暴触发能力必须绑定到rage组。
- Boss最多16阈值，生命严格低于才触发。狂暴时长必须显式填写。
- Encounter：当前地图2使用唯一ID1；指定赏金物品、警戒基点倍率和第二波出生ID列表。
  第二波仅普通/精英。两波存活怪、尸体与每召唤者最多一个召唤物合计不超过63，
  最坏掉落实例不超过64。

## 场景与探索

- SceneAction 唯一关联 SceneIdx。Mode=instant 时 HoldTicks=0，channel 时为正数。
  仅支持 supply、ladder、clue。开始与完成都核对距离，移动等其他动作或受伤会中断。
- Barrel：Scene.Kind=barrel，Hp、FuseTicks、Radius、Damage 必填。子弹击毁后点燃，
  爆炸命中立即引爆，每桶只结算一次；桶不接受普通交互。
- Region：2–16区域，每区1–2个clue场景和至少一个Boss出生候选。线索有显式交互配置。
  Boss与线索必须处于所属区域且只归属一区；全部Boss候选和clue都必须有归属。
- 旧三场景未选择新表时保持原行为，不据旧尺寸推断时间、伤害或奖励。

## 导出与经济参数

运行 `python -B export/gameplay.py --source design/demo_sources.json --check` 校验正式闭包。
Python只选取和序列化；Lua统一构建v5内容及摘要。通用 `export.py --check` 会读全部草稿，
仍报告历史Map重名、不完整MonsterSkill，不能以任意补零来让草稿进入生产。

`career=false` 表示永久出战和成长参数尚未提供。启用必须完整配置 levels（累计经验阈值，
首项0）、kill_xp（每种非召唤怪）、extract_xp、bounty_xp、bounty_currency、retire_xp。
当前只在明确数值的测试夹具验证，测试示例不作为正式经济参数。

角色表提供 Career（唯一ID1）、CareerLevel、KillXp 空模板。启用必须同时选入三表。
CareerLevel 主键从1连续，Xp 为累计经验；KillXp 按 MonsterIdx 唯一关联。只选等级或击杀
奖励而未选择 Career 会被拒绝；不完整的经济配置不会自动免费或自动发奖。
