# 技能表完整配置方案

编制日期：2026-10-03。适用工作簿：[技能表.xlsx](技能表.xlsx)，包含 `技能|Skill`、`属性|Attribute`、`技能效果|SkillEffect` 三张工作表。

本版给出推荐字段结构、15 项技能、16 项属性和 16 条技能效果的完整配置。医疗包使用时间减半、治疗量翻倍、复活满血和开箱额外 1 个道具来自已有技能描述。其余数值为本版建议初值，供调试与策划评审，尚未填写到 Excel，也不代表已经完成数值平衡验证。

当前服务端已有 11 项技能的机制，技能 3、6、14、15 仍需新增规则。本版包含属性外键和启用开关等字段调整，需配套修改配置解析后使用。杀怪掉落资源、道具箱真实奖励来源继续由补充策划案提供。

## 1. 三张表怎样分工

| 工作表 | 保存内容 | 与其他表的关系 |
| --- | --- | --- |
| `技能\|Skill` | 技能 ID、名称、技能点成本、作用对象、生命周期、启用状态和展示资源 | 一项技能对应一条 `Skill` 记录和一至八条效果记录 |
| `属性\|Attribute` | 稳定属性代码、名称、作用对象、单位、可用运算和参数语义 | 一个属性可被多个技能引用，属性代码只在这里维护 |
| `技能效果\|SkillEffect` | 哪个技能修改哪个属性、使用什么运算、参数是多少 | `SkillIdx` 引用技能表，`AttributeId` 引用属性表 |

例如“灵缇”由技能表定义名称及成本，属性表定义 `run_speed` 的单位是毫米/Tick，效果表配置 `mul_bp=12000`。奔跑速度基础值仍来自角色表 `Run`，无需在技能表重复填写。

基础属性仍归属角色、武器、工具等原始配置。动作触发位置、适用道具筛选和技术边界由对应属性处理器实现，属性表中的代码不能作为脚本执行。

## 2. 与现有字段相比如何调整

| 表 | 现有字段 | 推荐调整 | 原因 |
| --- | --- | --- | --- |
| Skill | `SkillIdx`、`Name`、`Desc`、`Cost` | 保留 | 保持原技能 ID、名称和成本，方便旧引用迁移 |
| Skill | `SkillType` | 删除 | 当前没有明确执行语义，容易与类别、生命周期混淆 |
| Skill | `SkillAttribute` | 删除 | 技能的属性关联统一放到效果表，一项技能可有多条效果 |
| Skill | `EffectDesc` | 保留为客户端展示字段 | 展示实际效果，不参与运行计算 |
| Skill | `Target`、`Category`、`Lifetime` | 保留并固定枚举 | 明确作用对象、数值/机制类别和消费时机 |
| Skill | `IconId`、`AnimId`、`EffectId`、`SoundId` | 保留为客户端资源字段 | 资源尚未交付时可以留空 |
| Skill | 无 | 新增 `Enabled`，`int32`，只允许 0/1 | 允许完整保留未实现技能，避免误加入可选择内容 |
| Attribute | `AttributeId`、`Name` | 保留，原 1～10 ID 不变 | 保持属性身份稳定 |
| Attribute | `AttributeType` | 删除，新增 `Target` | 用 `player/weapon/tool` 代替含义不清的数字分类 |
| Attribute | 无 | 新增 `Stat`、`Unit`、`AllowedOps`、`ValueMode` | 建立可校验的属性字典 |
| SkillEffect | `EffectIdx`、`SkillIdx`、`Op`、`Value` | 保留 | 继续采用一行一个效果和整数运算 |
| SkillEffect | `Stat` | 改为 `AttributeId`，类型改为 `int32` | 通过属性外键避免属性代码拼写错误及重复维护 |

推荐目标结构中，效果表只填 `AttributeId`，不同时保留一个可编辑的 `Stat`。解析时从属性表查出 `Stat`，仍投影为现有运行结构 `{stat, op, value}`。

本次不增加技能等级、技能依赖、冷却公式或复杂条件表达式。一个技能 ID 本局最多持有一次，常驻属性不需要各自填写动作冷却。

## 3. Excel 表头与导出约定

三张表都沿用项目已有的四行表头：

| 行号 | 内容 |
| --- | --- |
| 第 1 行 | 非空中文字段说明 |
| 第 2 行 | 类型，只使用当前工具支持的 `int32`、`string` |
| 第 3 行 | 下文规定的英文字段名，大小写一致 |
| 第 4 行 | `server`、`client`、`key` 等导出标记 |
| 第 5 行起 | 数据记录 |

字段从 A 列连续声明。每表只有一个 `int32` 主键，标记包含 `server/client/key`。ID 使用正整数；普通整数单元格不能留空，不填百分号、不填小数、不写 Excel 公式。资源字符串和展示字符串允许留空。

下面的 TSV 区块以制表符分列，可复制到工作表 A1。Skill 数据行中连续的制表符表示资源字段为空，不要把“待填”“空”写成资源 ID。

## 4. 技能表 Skill

### 4.1 推荐字段

| 列 | 中文说明 | 英文字段 | 类型 | 导出标记 | 填写规则 |
| --- | --- | --- | --- | --- | --- |
| A | 技能ID | `SkillIdx` | int32 | server/client/key | 唯一正整数，沿用现有 1～15 |
| B | 技能名称 | `Name` | string | server/client | 必填 |
| C | 技能说明 | `Desc` | string | client | 描述设计意图，不解析执行 |
| D | 消耗技能点 | `Cost` | int32 | server/client | 0～10000；本版全部沿用 1 |
| E | 作用对象 | `Target` | string | server/client | `player`、`weapon`、`tool` |
| F | 效果类别 | `Category` | string | server/client | `numeric` 或 `mechanic` |
| G | 生命周期 | `Lifetime` | string | server/client | `passive`、`once`、`death` |
| H | 效果展示说明 | `EffectDesc` | string | client | 与效果参数一致，修改参数时同步修改文案 |
| I | 技能图标 | `IconId` | string | client | 真实资源 ID；未交付留空 |
| J | 动画资源 | `AnimId` | string | client | 需要表现时填写；普通被动技能可以为空 |
| K | 特效资源 | `EffectId` | string | client | 真实资源 ID；可以为空 |
| L | 音效资源 | `SoundId` | string | client | 真实资源 ID；可以为空 |
| M | 是否启用 | `Enabled` | int32 | server/client | 0 禁用，1 纳入本版可选择技能候选 |

### 4.2 枚举含义

| 字段 | 值 | 含义 |
| --- | --- | --- |
| Target | player | 修改猎人自身能力；开箱奖励次数也作为猎人能力保存 |
| Target | weapon | 修改已配装枪械的对应属性 |
| Target | tool | 修改符合该属性处理器适用条件的工具 |
| Category | numeric | 修改基础属性或容量 |
| Category | mechanic | 改变复活、交互奖励等机制 |
| Lifetime | passive | 持有且未失效时持续生效；常驻的开箱机制也使用此值 |
| Lifetime | once | 本局只成功触发一次；成功后标记已消费 |
| Lifetime | death | 按现有代码语义，在成功复活提交时移除；死亡瞬间不提前移除 |
| Enabled | 0 | 保留完整配置和说明，不允许购买、配装、拾取或作为默认技能发放 |
| Enabled | 1 | 允许进入候选内容；仍须通过实现能力、参数和来源完整性校验 |

`Enabled` 是本版新增的目标规则，当前代码尚未读取它。禁用技能仍检查字段、外键和参数格式；只有启用技能进入运行时 `content.skills`，并接受处理器已实现检查。禁用技能的关联物品或默认配装也不能出现在启用内容中。

本版 TSV 的 1 表示“建议调试时启用”，不是发布批准。建议初值尚未确认时，正式配置继续保持草稿；完整生产内容仍由显式选表清单决定。

技能 2 沿用当前行为：可以单独持有，但单独持有不能复活。若以后要求购买或配装技能 2 前必须拥有技能 1，需另加明确依赖字段及选择校验。

## 5. 属性表 Attribute

### 5.1 推荐字段

| 列 | 中文说明 | 英文字段 | 类型 | 导出标记 | 填写规则 |
| --- | --- | --- | --- | --- | --- |
| A | 属性ID | `AttributeId` | int32 | server/client/key | 唯一正整数，原 1～10 保留，新增从 11 起 |
| B | 属性名称 | `Name` | string | server/client | 必填，供策划及界面解释 |
| C | 属性代码 | `Stat` | string | server/client | 唯一、稳定，必须对应已登记属性规则 |
| D | 作用对象 | `Target` | string | server/client | 与引用技能的 Target 一致 |
| E | 参数单位 | `Unit` | string | server/client | 固定单位代码，见下表 |
| F | 合法运算 | `AllowedOps` | string | server | `add`、`mul_bp`，多项用半角竖线分隔 |
| G | 数值语义 | `ValueMode` | string | server | `modifier`、`absolute`、`flag` |

单位枚举：`stamina_per_second` 体力/秒、`weight_point` 负重点、`mm_per_tick` 毫米/Tick、`mm` 毫米、`hp` 生命点、`round` 发弹药、`tick` Tick、`stamina` 体力点、`bool` 标记、`item` 道具个数、`use` 可携带次数。

| ValueMode | 参数解释 | 允许运算 |
| --- | --- | --- |
| modifier | 修改来源配置的基础值；额外奖励次数以 0 为基础值 | 以该属性 AllowedOps 为准 |
| absolute | 提供机制所需绝对值；复活生命、体力从 0 计算 | add |
| flag | 开启已实现的机制修饰，本版用于满血复活 | add，且 Value 只能为 1 |

`ValueMode=absolute` 时，`add=25` 表示“复活后设置为 25 点生命”，不是增加当前生命 25。`modifier` 的 `add` 才表示在来源基础值上增加固定量。

## 6. 技能效果表 SkillEffect

### 6.1 推荐字段

| 列 | 中文说明 | 英文字段 | 类型 | 导出标记 | 填写规则 |
| --- | --- | --- | --- | --- | --- |
| A | 效果ID | `EffectIdx` | int32 | server/client/key | 全表唯一正整数；推荐按“技能 ID ×100＋行序号”分配 |
| B | 技能ID | `SkillIdx` | int32 | server/client | 引用 Skill.SkillIdx |
| C | 属性ID | `AttributeId` | int32 | server/client | 引用 Attribute.AttributeId |
| D | 运算 | `Op` | string | server/client | 必须属于属性 AllowedOps |
| E | 参数值 | `Value` | int32 | server/client | 必填整数，语义由 Op 和 ValueMode 共同决定 |

效果 ID 只负责稳定身份，不参与计算或触发顺序。例如 101、102 均引用技能 1，但代码仍以 SkillIdx 外键关联，不能通过效果 ID 的前缀推导技能。

### 6.3 怎样理解 add 和 mul_bp

| 写法 | 含义 | 例子 |
| --- | --- | --- |
| modifier + add=1 | 基础属性增加 1 个该属性单位 | 负重 3 变为 4 |
| modifier + add=-10 | 基础属性减少 10 个单位 | 仅在该属性允许且最终值合法时使用 |
| modifier + mul_bp=10000 | 保持原值 | 100% |
| modifier + mul_bp=12000 | 基础值乘 1.2 | 增加 20% |
| modifier + mul_bp=7500 | 基础值乘 0.75 | 减少 25% |
| modifier + mul_bp=5000 | 基础值乘 0.5 | 减半 |
| modifier + mul_bp=20000 | 基础值乘 2 | 翻倍 |
| absolute + add=25 | 机制绝对参数为 25 | 复活后生命为 25 |
| flag + add=1 | 开启指定机制修饰 | 将复活后的生命覆盖为最大生命 |

`mul_bp` 使用万分比因子。减少 30% 填 7000，增加 30% 填 13000，不填 30、0.3 或 -3000。

同一属性按当前运算规则合成：

```text
固定增量 = 所有 add 参数之和
倍率因子 = 10000 + 所有 (mul_bp 参数 - 10000) 之和
最终值   = floor((基础值 + 固定增量) × 倍率因子 / 10000)
```

多条倍率的贡献相加。两个不同技能分别增加 20% 和 50%，合成因子是 17000；两个分别减少 25% 的效果合成因子是 5000。不得按技能获得顺序逐条相乘。

同一个技能内，同一个 AttributeId 只允许一条效果。若一个技能需要同属性的固定量和倍率组合，首版应先重新设计为一条明确效果，或另行扩展合成契约。

Value 的通用输入范围沿用现有门禁：`add` 为 -1000000～1000000；`mul_bp` 为 0～100000。绝对复活参数不得为负，标记只能为 1，额外奖励次数不得为负。倍率合成后也必须满足最终值边界。

运算结果向下取整，越界时拒绝配置或整份配装，不自动截断。例如使用时间基础为 1 Tick 时再减半会得到 0，必须报错；应调整来源参数或效果值。

## 8. 四项待扩展技能的完整规则建议

### 8.1 精力充沛：先建立奔跑扣耗

角色表 `RunCost` 目前为 0，现有校验只接受 0，移动逻辑没有持续扣体力。仅填写技能效果 301 不会产生效果。

建议在角色表将 `RunCost` 的字段说明改为“奔跑每秒体力消耗”，调试基础值填 10。保持原类型 `int32` 和字段名，不扩大到跳跃体耗；本版 `JumpCost` 仍为 0。

建议扣耗规则：

1. 仅在地面产生实际奔跑位移时扣耗，站立、撞墙不动、匍匐、爬梯不按奔跑扣耗。
2. 每 Tick 累加有效每秒扣耗，累计值整除 tick_hz 后扣整数体力，余数保留到下一次实际奔跑；停止奔跑不能通过清除余数规避消耗。
3. 扣耗余数与现有体力恢复余数分开。暂停不推进，恢复至满体力时可以清理扣耗余数，开始新的满体力周期。
4. 体力归零后回到普通移动，开始现有体力恢复延迟。建议要求松开奔跑键后重新按下才能再次奔跑，避免一直按住时在恢复1点后反复切换。
5. 新增扣耗余数和耗尽门禁的跨 Tick 状态由 C++ Player 保存，同步进入状态导入与恢复校验。

以 RunCost=10、tick_hz=60 为例，连续60个有效奔跑Tick消耗10体力；持有技能3后消耗7。RunCost=0 的来源配置即使乘7000仍为0，应提示该技能在该角色上无实际作用。

### 8.2 猫步：声音与视觉分别判定

推荐增加以下外部基础字段；这些是角色和怪物表的配套调整，不属于技能效果参数：

| 来源表 | 新字段 | 类型与标记 | 建议初值 | 单位/含义 |
| --- | --- | --- | --- | --- |
| Player | WalkNoiseRadius | int32，server/client | 6000 | 地面普通行走声传播半径，毫米 |
| Player | RunNoiseRadius | int32，server/client | 10000 | 地面奔跑声传播半径，毫米 |
| Player | ProneNoiseRadius | int32，server/client | 2000 | 地面匍匐声传播半径，毫米 |
| Monster | HearingRange | int32，server/client | 10000 | 怪物听觉最大距离，毫米；0表示不听声 |

本版建议视觉条件为“在原 DetectRange 内且视线无遮挡”，听觉条件为“本 Tick 有行动声，且距离不超过行动声半径和怪物 HearingRange 两者的较小值”。两个条件任一满足即可获取目标。

猫步只将行动声基础半径乘5000。第一版行动声按二维圆形传播，可以穿墙，不模拟材料衰减。行走、奔跑和匍匐均按实际位移发声；站着不动不产生这三种行动声。跳跃落地、爬梯等其他声源后续另设基础规则，本版不自动归入该效果。

当前怪物感知是在 DetectRange 内直接警戒，没有独立听觉。因此实施猫步时必须同步修改感知入口。保留原无条件距离获取，再单独降低声音范围，不能验证出正确的潜行收益。

复活后现有新目标获取抑制门禁仍优先执行。枪声、爆炸声、视觉距离和警戒持续时间不受猫步倍率影响。客户端降低音量可作为表现调整，但不替代服务端半径规则。

验收示例：怪物DetectRange=6000、HearingRange=10000，玩家在8000毫米外奔跑时，无猫步可通过听觉发现，持有猫步时听不到；玩家在无遮挡的4000毫米处仍可通过视觉被发现。隔墙时，视觉应失败，再单独判听觉。

### 8.3 开箱大师：额外道具在一次提交中生成

本版技能14保持 Disabled，直到适用箱子和真实奖励来源接入。当前 `supply` 是工具补给点，不能自动把所有 supply 当成策划中的奖励道具箱。

推荐完整行为：

1. 后续箱子配置标明是否属于适用道具箱，并绑定自己的奖励来源。技能只提供额外数量1，不指定怪物掉落表、道具ID或奖励池ID。
2. 完成交互时读取猎人当前有效技能。先生成箱子基础奖励，再从同一箱子的奖励来源取得额外1个道具单位。
3. “1个”定义为数量1，允许与基础奖励为同一道具并按合法规则堆叠；不是额外生成一整组随机数量，也不要求一定获得新道具种类。
4. 形成包含全部物品变化和箱子已使用状态的候选，核对背包/工具数量及实体容量，再一次原子提交。
5. 本版推荐容量不足时整笔拒绝：不发基础奖励、不发额外奖励、不消耗箱子。调整空间后可重试。失败还须保留随机状态，重试不能通过连续失败刷新奖励。
6. 同一箱子本局只成功开一次；迟到、重复请求、交互中断或终局请求不再次发奖。

真实箱子资源仍待补充策划，不能在本版填写虚构奖励引用。机制可以用独立的奖励夹具验证基础1个＋额外1个、相同物品叠堆、不同物品占格及容量失败。

### 8.4 货运骡子：提升单种非消耗品工具容量

“携带量”的口径已由用户确认：每种非消耗品工具的携带数量／可用次数增加。本版按每种适用工具的携带次数上限实现，增加1为建议初值。当前工具表 `ToolType=1` 对应非消耗品工具，`ToolType=2` 对应针剂、炸药等消耗品。非消耗品工具的使用次数仍可能减少，并可由补给恢复。

推荐在工具表增加 `CarryLimit`，类型 `int32`、标记 `server/client`，单位为可携带次数；原 `Quantity` 保留为基础初始化数量。源配置必须满足 `1 ≤ Quantity ≤ CarryLimit ≤ 100`。

| 工具ID / 名称 | 当前 Quantity | 建议基础 CarryLimit | 技能15有效容量 | 首版适用情况 |
| --- | --- | --- | --- | --- |
| 30001 匕首 | 1 | 1 | 1 | 排除；刀不通过该技能增加次数 |
| 30002 急救包 | 3 | 3 | 4 | 适用，是当前已实现的非消耗品次数工具 |
| 3 照明棒 | 5 | 5 | 6 | 未来该工具实现后可纳入；目前不能启用其运行内容 |
| 30004 生命针剂 | 1 | 1 | 1 | 排除，属于消耗品 |
| 5 恢复针剂 | 1 | 1 | 1 | 排除，且当前尚未实现该具体工具 |
| 30006 炸药束 | 1 | 1 | 1 | 排除，属于消耗品 |

技能只计算有效 CarryLimit，不直接增加当前 count 或永久库存。普通独立夹具仍按 Quantity 初始化，急救包为3/4；拥有4次实际库存的永久猎人可带入4/4，库存只有3次时带入3/4。

补给可以在有效容量内恢复次数。配装、初始化、补给、拾取、导入、永久出战和结算统一使用同一有效容量。永久结算须保存本局实际带入量并据此计算返还，不能继续用旧基础 uses 代替实际带入量；补给不得凭空增加可结算库存。

若未来允许局中移除该技能，本版建议仅在当前数量不超过新容量时接受移除；超过时返回容量冲突，不静默删除道具。现有局外移除、装备选择和出战占用也须按相同规则校验。

## 10. 三表必须执行的校验

| 层次 | 必须检查 |
| --- | --- |
| 字段 | 固定字段和类型；整数不为空，不接受公式；Enabled只允许0/1 |
| 身份 | 各表主键唯一；Attribute.Stat唯一；稳定ID不能随意重编号 |
| 外键 | 每个SkillEffect.SkillIdx存在；每个AttributeId存在；无孤立效果 |
| 技能内容 | 每项技能1～8条效果；同技能同属性不能重复；资源缺失不影响纯服务端机制验证 |
| 对象 | Skill.Target必须等于所引用Attribute.Target；Category和Lifetime符合该机制的约定 |
| 运算 | Op在AllowedOps中；Value是合法整数；AllowedOps和ValueMode与登记处理器一致 |
| 机制组合 | 技能1生命/体力成对且为player/mechanic/once；技能2为player/mechanic/death且仅flag=1 |
| 能力 | 启用技能必须有真实已实现处理器；3/6/14/15未完成时拒绝Enabled=1 |
| 数值 | 在具体角色与装备上计算最终值；检查技术范围、角色上限和合成后倍率 |
| 引用闭包 | 启用默认配装、技能物品等不得引用禁用技能；正式显式来源必须选入所需Skill、Effect和Attribute |
| 身份摘要 | 属性代码、运算、数值及启用集合变化均重新生成对应内容身份，客户端与服务端保持一致 |
| 展示 | EffectDesc与实际效果一致，百分比按万分比解释；资产与治疗结果以权威状态为准 |

建议的错误定位应包含工作簿名、工作表、源行号、主键和具体问题，例如“SkillEffect 第8行，EffectIdx=301，技能3尚未实现，不能启用”。

校验 Disabled 行只验证结构和声明参数，不执行尚未实现的业务；Enabled行不能通过忽略错误、默认填0或自动补测试数值继续发布。

| [loadout.lua](../server/lua/game/loadout.lua)、[inventory.lua](../server/lua/game/inventory.lua)、[career.lua](../server/lua/game/career.lua)、[statecheck.lua](../server/lua/game/statecheck.lua) | 初始化数量与容量分开；永久出战和结算核对实际带入量；导入检查动态有效容量 |
| C++ Player/World、状态schema | 保存新增跨Tick余量、门禁或提交状态；同步桥接、导入、恢复与必要版本调整 |
| 客户端表生成与Hunter协议适配 | 同步AttributeId外键、Enabled、技能展示及有效数量，复用动作表现并读取权威结果 |
| 导表及玩法测试 | 改旧Stat效果夹具为AttributeId＋Attribute字典；验证外键、禁用门禁、摘要变化、机制组合和数量一致性 |

当前解析完全不读取Attribute，且SkillEffect仍直接读取Stat。因此不能只把效果表列名改成AttributeId就导出运行。也不要只新增Enabled列后假设现有解析会自动过滤禁用技能。

如果共享内容结构或原生跨Tick状态发生变化，按现有版本契约同步升级；表层外键转成原有stat/op/value形状时可以保留现有技能运算接口，但必须重新生成内容身份。
