# Server 工作约定

## 当前阶段

本目录已建立规划与工程结构，尚未进入实现阶段。设计基线见 [plan.md](plan.md)。

- `.gitkeep` 仅用于保留空目录。
- Lua 文件目前仅包含职责说明，不代表功能已实现。
- `lua/modules.json` 的空对象仅作文件占位，不定义正式清单 schema 或加载行为。
- 不因目录和文件已经存在，就将相应阶段、模块或测试标记为完成。

## 后续开发流程

收到具体实现任务后，按以下顺序工作：

1. 阅读 `plan.md`，确认任务范围和前置依赖。
2. 在 `intents/` 中建立或更新对应设计契约，并阅读适用的 `rules/`。
3. 明确不变量、线程与所有权、接口、失败行为和验证入口。
4. 根据契约补充有意义的测试，再实现并记录验证结果。

尚未建立的 intent 和规则属于待办设计，不能视作现有实现。不得将延期内容自动加入当前任务。

## 目录与协作边界

- `src/` 放共用 C++ 核心，`platform/` 放 Android 与桌面宿主适配。
- `lua/main.lua` 负责组装和入口分发，玩法放在 `lua/game/`，通用脚本支持放在 `lua/framework/`。
- `tools/` 放服务端专用脚本与制品工具；通用导表继续使用仓库根目录 `export/`。
- 协议继续使用根目录 `protobuf/`，配置源表使用 `design/`，不建立重复来源。
- 正式发布面向 Android 随包双进程，Windows 用于开发；Luax 的线程、重入、模块授权和数据边界以规划及固定候选的实际接口为准。

## 验证与进度

目录、注释或规划调整只检查相应结构、格式与引用，不要求编写业务测试。后续实现运行与改动相关的契约和集成验证；Android 行为必须包含真机证据，不能以 PC 通过代替。

进度说明区分已规划、已实现和已验证，记录实际执行结果，不将占位文件或未运行的测试作为完成证据。
