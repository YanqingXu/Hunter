# R-REFACTOR：Hunter 重构与复杂度评审规则

适用于本次新增或实际修改的服务端 C++、Luax、平台适配与工具代码，以及明确约定范围的专项重构。
等级与设计基线见 [规则入口](README.md)，设计理由见 [编码原则](coding_principles_rules.md)。
代码异味是调查信号，不等于 Bug，也不授权扩大修改范围。

## 1. 行为与范围

### R-REFACTOR-01 重构保持可观察行为

- **等级：MUST。** 先列出本次需保持的行为，再改内部结构。修复业务错误、修改 schema、协议、
  奖励或存档策略属于行为变化，应在任务与验证中单独说明，不能全部称为重构。
- Hunter 的行为边界包括返回值、错误码、消息与存档内容、外部调用顺序、状态转换、随机数消耗、
  Tick／暂停时序、脚本入口与 Host schema、线程归属、取消、失败终态及资源释放。
- 结构变更不得悄悄调整输出缓冲提交、`Accepted`／`Committed`、事务去重或未完成局处理方式。
- **验证：** 记录受影响行为、对应契约、改动前基线、针对性回归结果与必要的恢复方法。
  编译通过不是行为等价证明；只涉及文档与排版时使用与其风险相符的检查。

### R-REFACTOR-02 模糊命名先澄清真实意图

- **等级：MUST（确认意图缺失时）。** 使用项目术语命名状态、动作、单位与领域事实，
  不以注释弥补可以通过命名解决的歧义。
- `data`、`tmp` 等名称只触发上下文检查，不能依赖词表自动改名。
- **验证：** 重命名前检查代码、字符串注册、脚本入口、模块清单、配置、协议及生成映射中的引用。
  对外入口名称本身可能是行为契约，不能只依赖编译器查引用。

## 2. 职责与抽象

### R-REFACTOR-03 长函数按混合职责评审

- **等级：REVIEW。** 函数难以局部理解、包含多个抽象层或多个独立阶段时，检查提取函数的收益。
- 约 60 行、10 个决策点或三层嵌套可作为阅读提示，不是硬阈值；多个指标同时命中也不自动重构。
- 按完整业务阶段拆分，保留失败位置、处理顺序和收尾。固定表驱动或严格时序流程可以保持集中。
- **验证：** 提取后顶层流程更易理解，且没有复制状态、漏掉分支或扩大公共接口。

### R-REFACTOR-04 长参数列表先确认领域概念

- **等级：REVIEW。** 参数超过五个，或同一字段组在多处反复出现时，检查是否存在稳定概念。
- 参数对象需表达不变量或真实边界；不为降低参数计数创建无语义对象，也不传入整个世界状态
  让函数获得不必要的修改权限。
- **验证：** 保持参数方向、默认值、所有权、生命周期、数值宽度、调用顺序及接口契约。

### R-REFACTOR-05 基础类型抽象需要领域证据

- **等级：REVIEW。** 不同 ID、时间或坐标出现误传、重复校验或单位混淆时，可引入枚举、值类型
  或已有强类型；无需批量包装所有整数。
- C++ 内部类型变化不能隐式改变 Protobuf、Host 数值表示、状态快照或 SQLite schema。
  跨界 64 位 ID 必须保持精度，不能为了统一表示改成浮点数。
- **验证：** 核对序列化、ABI、值范围、热路径成本与 Windows／Android 工具链支持。

### R-REFACTOR-06 混合职责按所有者拆分

- **等级：REVIEW。** 一个模块同时因传输、玩法、存档和宿主生命周期等独立原因变化时，
  优先把职责放回规划已有的边界。
- `main.lua` 负责组装，不逐步堆成全部玩法；Storage 负责事务，不负责奖励算法；
  平台适配不直接修改世界状态。
- 不为降低文件或类大小创建没有当前用途的 Manager、Service 或 Framework。
- **验证：** 对照规划第 2、3 节，检查依赖方向、可见接口与状态归属。

### R-REFACTOR-07 同一知识收敛到权威来源

- **等级：MUST（确认同一知识时）。** 同一规则必须同步改多处时，确认权威表示，
  将派生内容交给生成、共享实现或一致性校验。
- 协议、配置与导表沿用根目录来源；C++ 与脚本不各维护一套权威战斗或奖励逻辑。
- 语法相似但变化原因不同的代码可以保留，不能只凭重复文本合并。
- **验证：** 从一次实际规则修改追踪所有使用方，确认没有遗漏派生产物或隐藏副本。

### R-REFACTOR-08 行为放在拥有数据与职责的边界

- **等级：REVIEW。** 函数大量依赖别的模块内部字段时，检查行为是否放错位置。
- 移动函数不能越过线程、VM 或存档连接的所有权边界，不能为减少访问次数把对象直接跨线程借用。
- **验证：** 核对调用方向、所属线程、数据副本、借用期限与状态唯一性。

### R-REFACTOR-09 深成员访问检查知识泄漏

- **等级：REVIEW。** 多次穿过四层及以上对象访问，或重复依赖相同内部路径时，检查是否需要
  由所有者提供更明确的入口。访问层数不是自动错误。
- 不以新的透传层掩盖错误依赖，也不把只读查询改成隐式状态修改。
- **验证：** 调用者减少对内部结构的依赖，同时错误语义、所有权和成本保持清楚。

### R-REFACTOR-10 删除封装前确认边界价值

- **等级：REVIEW。** 纯转发且无领域语义的函数或类可以内联；Host 转换、平台适配、能力约束、
  测试替身与兼容接口即使很薄，也可能需要保留。
- **验证：** 对照 `R-READABILITY-06`，检查内联是否破坏能力限制、错误转换或替换边界。

### R-REFACTOR-11 抽象回应当前需求

- **等级：MUST（引入抽象时）。** 新接口、工厂、注册表、策略或框架层需能说明当前变化轴、
  实际第二实现、测试边界或风险隔离需求；无法说明时选择直接函数或普通组合。
- Android／Windows 宿主适配具有当前依据，未来多房间、跨服和在线经济系统不属于首版依据。
- **验证：** 给出实际使用点与简要理由，不要求额外流程报告或仅为了凑第二实现编写空壳。

## 3. 操作纪律与条件逻辑

### R-REFACTOR-12 小步修改并获得有效反馈

- **等级：MUST。** 人工和工具辅助重构均遵循同一流程：
  1. 确认任务范围，阅读规划、适用 intent 与规则，建立真实行为基线。
  2. 每一步做一个可说明的变换，例如重命名、提取、移动或封装。
  3. 检查所有引用及失败、副作用、所有权和调用顺序，运行能发现当前风险的针对性验证。
  4. 检查 diff，在有意义的检查点完成整体验证，记录执行结果与证据盲区。
- 发现必须改变行为、扩展任务范围或缺少关键契约时，先澄清并更新相应设计；不带着未解释的
  验证失败继续叠加变换。没有运行条件时如实记录未验证，不宣称等价或已通过。
- 不要求外部项目的 Agent 流程、allowlist、报告 schema 或检查工具，也不自动展开多 Agent 任务。
- **验证：** 每个变换能独立解释，恢复方式不会覆盖他人已有改动；与本任务无关的格式和重命名不混入。

### R-REFACTOR-13 按复杂度成因选择手法

- **等级：REVIEW。** 嵌套遮蔽正常路径、重复分派、循环混合职责或抽象层交错时，先说明成因，
  再选择改动最小的手法。

| 成因 | 候选手法 | 必须保持的边界 |
| --- | --- | --- |
| 失败分支包裹正常流程 | 卫语句或提前结束当前迭代 | 不跳过资源释放、事务、状态恢复或完成通知 |
| 单个循环交错承担多个阶段 | 提取阶段或拆分循环 | 保持数据依赖、失败时机、遍历与随机顺序；热点增加遍历需测量 |
| 稳定类型在多个行为中反复分派 | 既有表驱动、组合或多态 | 确有替换需求；不为了消除一个 `switch` 建继承体系 |
| 高层裁决与底层处理交错 | 提取完整子流程、移动到所有者 | 保持线程、所有权、输出提交和错误边界 |

- 不以减少行数、分支数或缩进为唯一收益，也不为满足指标制造临时容器或共享缓存。
- **验证：** 覆盖正常路径与失败出口；涉及 Tick 热点时比较实际规模和耗时，涉及多态时核对
  生命周期与替换契约，不能用风格改善代替性能或行为证据。

### R-REFACTOR-14 条件判断按业务意图选择最小改动

- **等级：MUST（保持语义）；REVIEW（选择手法）。** 跨行条件、多个布尔项或复杂取反触发阅读
  检查，不强制提取函数。清楚的空值、范围或状态组合可以就地保留。
- 条件表达独立业务问题或重复知识时，可提取只读谓词或命名局部结果；名称表达“能否撤离”、
  “是否当前代次”等事实。谓词不夹带发包、写库、奖励修改或依赖调用次数的日志。
- `A && B` 或 `A || B` 清楚时可直接返回；卫语句用于突出拒绝原因与正常路径，不要求逐项
  拆散所有布尔表达式。混合逻辑必须保留分组、短路与左右求值顺序。
- 原条件有副作用时，只能在保持原执行路径的前提下分离操作和判断；不能把受空值检查保护的
  成员访问提前放到函数实参里，也不能提前计算所有条件。

| 情形 | 处理方向 |
| --- | --- |
| 业务判断难以命名或混合多个层级 | 先确认领域事实，再选择局部结果、只读谓词或拆分阶段 |
| 多个判断产生相同结果 | 仅在同一业务原因且求值与失败顺序不变时合并 |
| 各分支有重复动作 | 核对与其他副作用的相对顺序后，再移动或提取 |
| 重复判断合法的特殊状态 | 可考虑统一表示；不能将损坏存档或非法请求伪装成正常对象 |
| 内部不变量未表达 | 可补断言；外部输入仍需运行时校验，不能依赖发布构建执行断言 |
| 控制标记仅决定循环退出 | 可改为 `break`、`continue` 或 `return`，前提是不改变退出范围与收尾 |

- **验证：** 对实际改变结构的复杂条件记录简要决策表或等价分支说明，覆盖原子条件、短路跳过
  路径、边界值和失败出口。核对返回值、错误码、随机数、状态、输出与存档的内容和顺序。
  简单改名或排版不要求机械生成完整矩阵；存档与生命周期改动仍需对应契约验证。

## 4. 按影响选择验证

下表描述后续实现所需证据，不表示当前已有这些测试或运行入口。

| 改动范围 | 应核对的行为与验证 |
| --- | --- |
| 局部表达与 helper | 现有单元／脚本测试、代表性输入、失败与边界路径、引用及 diff |
| 玩法与 Tick | 固定种子和输入的可复现结果、随机消耗、死亡与撤离互斥、暂停不推进时间 |
| 传输与 Host 桥接 | 分帧和队列边界、参数校验、线程错误、重入拒绝、过期句柄、取消与重复完成 |
| 存档与结算 | 同 ID 同内容重试、冲突拒绝、提交前后强杀、写入失败与重启查询 |
| 热更新 | 安全点、Busy、状态与代次连续、旧完成事件处置、候选失败不污染原实例 |
| Android 宿主与发布 | 真机启停、锁屏／前后台、任一进程死亡、监听与数据库资源释放、离线包完整性 |

Android 退出验证检查运行资源释放，不要求缓存进程 PID 立即消失。
测试优先断言公开行为与不变量，不锁死私有 helper、内部容器或无契约意义的调用细节。
不重复运行与改动无关的大范围检查；缺少真实验证入口时说明限制，不能用占位文件作完成证据。
