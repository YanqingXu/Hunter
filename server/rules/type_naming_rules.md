# R-TYPES：服务端 C++ 短类型命名规则

短类型的唯一声明来源是 [src/common/Types.h](../src/common/Types.h)。
本规则适用于所有服务端自有 C++ 代码，包括核心、平台适配、测试、工具和项目维护的代码生成模板；
第三方库源码及头文件不适用。调用第三方库的项目代码仍须遵守本规则。
本规则覆盖全量自有代码，不限于新增或修改行。等级含义见 [规则入口](README.md)。

### R-TYPES-01 已有短类型必须统一使用

- **等级：MUST。** 显式书写 `Types.h` 已覆盖的类型时，统一使用对应短类型，不能混用其原始
  STL、固定宽度整数或浮点类型拼写。适用于成员、局部变量、参数、返回值、模板实参、类型转换
  和后续领域别名的定义。
- 下表是现有声明的使用对照；实际定义以 `Types.h` 为准，修改定义时同步更新本表。

| 原始类型 | 统一短类型 |
| --- | --- |
| `std::int8_t` / `std::uint8_t` | `i8` / `u8` |
| `std::int16_t` / `std::uint16_t` | `i16` / `u16` |
| `std::int32_t` / `std::uint32_t` | `i32` / `u32` |
| `std::int64_t` / `std::uint64_t` | `i64` / `u64` |
| `std::size_t` | `usize` |
| `float` / `double` | `f32` / `f64` |
| `std::string` | `Str` |
| `std::vector<T>` | `Vec<T>` |
| `std::unordered_map<K, V>` | `HashMap<K, V>` |
| `std::map<K, V>` | `Map<K, V>` |
| `std::unordered_set<T>` | `HashSet<T>` |
| `std::set<T>` | `Set<T>` |
| `std::shared_ptr<T>` | `Ptr<T>` |
| `std::weak_ptr<T>` | `WPtr<T>` |
| `std::unique_ptr<T>` | `UPtr<T>` |
| `std::function<Signature>` | `Func<Signature>` |

- 项目自行选择的整数类型按值域、符号和用途使用 `i8`～`i64`、`u8`～`u64` 或 `usize`，
  不继续用 `short`、`int`、`long`、`unsigned` 等平台相关拼写表达业务数值。
- `usize` 表达内存大小、容器长度及索引，不能作为跨端协议或持久化字段的隐式宽度。
- `bool`、`char`、`void` 等未定义短别名的基础类型，以及领域类、枚举和模板参数，保留准确类型名，
  不为了缩短名称改变含义；字符不能机械替换成 `i8` 或 `u8`。
- **验证：** 检查所有显式类型位置，包括嵌套模板；原始类型仅可出现在别名定义和下述契约边界中。

### R-TYPES-02 统一定义并直接包含依赖

- **等级：MUST。** 使用短类型的文件直接包含 `Types.h`，不能依赖其他头文件偶然间接包含。
  头文件必须能独立获得其使用的别名定义。
- 以 `server/src/` 为包含根时使用 `#include "common/Types.h"`；后续构建配置需向使用这些
  类型的目标提供该包含路径，不为此恢复独立的 `include/` 目录。
- `Types.h` 的别名定义必须引用底层真实类型，因此该文件中的 `std::` 和基础类型拼写是定义所需，
  不属于违规。不在其他模块复制同名别名，也不使用宏或 `using namespace std` 绕过规则。
- 新增通用短类型、支持自定义分配器／比较器／删除器等参数时，先在 `Types.h` 统一定义并验证，
  不在业务模块自行发明另一套缩写。现有别名无法表达的类型不能强行套入默认参数版本。
- 稳定的领域类型可以在所属模块定义，例如基于 `u64` 的领域别名；短类型统一要求不禁止真正的
  强类型或值对象。`R-READABILITY-07` 对无意义缩写的限制不禁止本文件统一规定的短类型。
- **验证：** 检查别名声明唯一性、直接依赖和实际构建包含路径；编译证据以实际目标和验证记录为准。

### R-TYPES-03 使用别名不改变类型语义

- **等级：MUST。** 替换类型拼写必须保持真实类型、值域、符号、宽度、`const`、引用和指针限定，
  同时保持重载选择、模板匹配、序列化与 ABI。
- 不将所有整数直接换成 `i32`，也不因 `UPtr` 名称简短而改变原本共享或观察关系。
  `Ptr` 表示共享所有权，`UPtr` 表示独占所有权，`WPtr` 表示弱引用，三者不能互换。
- `auto`、`decltype` 可在推导清楚时使用；显式模板实参和类型转换仍使用短类型，不为规避规则
  将本来需要明确宽度或所有权的声明全部改成 `auto`。
- `std::move`、`std::make_unique` 等函数和工厂保留原名；它们不是需要替换的类型拼写。
- **验证：** 已有代码的类型迁移按 [重构规则](refactoring_rules.md) 检查真实类型与行为，
  不能以命名统一为理由跳过兼容性或边界验证。

### R-TYPES-04 外部契约在接入边界保持准确

- **等级：MUST。** 第三方库保持上游代码；项目接入层对于已有等价短别名的类型仍使用短名，
  不因调用第三方 API 就豁免整个文件或模块。
- 标准入口、JNI、平台 ABI、第三方回调和生成接口要求的准确类型优先保持契约；仅在别名与要求
  的类型完全相同时才替换。不能把平台句柄、`jint` 等专用类型按“位数看起来相同”替换为项目整数。
- 边界确需保留外部类型时，将其限制在入口或适配层；进入项目内部后按明确转换与范围校验使用短类型。
  记录非显然的类型约束，不把这条当作普通业务代码保留长类型名的理由。
- 项目维护的生成模板必须输出短类型。Protobuf 等第三方生成器控制的代码保留生成契约、不得
  手工替换产物；项目侧适配与使用代码仍受本规则约束。
- **验证：** 检查边界签名、类型等价性、转换范围及生成来源，避免批量文本替换改变接口。

### R-TYPES-05 自检覆盖全量自有代码

- **等级：MUST。** 评审时搜索原始类型拼写，再结合声明上下文排除第三方、别名定义及外部契约。
  文档、字符串、函数名中的相同文字不能直接当成代码违规。
- 不得只检查 `src/` 而漏掉 `platform/`、`tests/` 或 `tools/` 中的自有 C++。
- 当前通过搜索和语义评审执行，没有自动短类型检查器。未来增加工具时，须覆盖模板、类型别名、
  边界声明及生成代码分类；正则命中不直接证明真实类型或兼容性。

## 使用示例

以下只说明项目类型拼写，不定义正式玩法接口：

```cpp
#include "common/Types.h"

struct LootEntry
{
    u64 item_id;
    i32 count;
    Str name;
};

using LootList = Vec<LootEntry>;

using CommitCallback = Func<void(u64, bool)>;
```
