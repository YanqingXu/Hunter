Hunter 配置导出工具

正式导出
1. 保存 design 目录中源表的修改。
2. 双击 export/导出配置.exe，查看结果窗口。

正式来源为 design 根目录中的全部 .xlsx 配置工作簿，不再读取生产 JSON 清单。
默认入口与服务端构建读取相同目录；导出目标.txt 只影响旧草稿入口。
含“中文名|EnglishName”的工作表按 server 标记导出全部数据行，Office 临时文件和无 | 的说明表跳过。
必需配置、启用状态、关联记录和玩法数值由同一份 Lua 规则校验，缺值不会自动补入。

文件与输出
- Excel 源文件保存在 design，EXE 保存在 export，不要单独移动 EXE。
- 不需要安装 Python 或 Excel 插件；开发人员需准备好固定 Luax 工具和项目 Lua 脚本。
- Lua 表输出到 server/build/generated/cfg，每表一个文件，例如 Player.lua、Weapon.lua。
- 生成目录中的 Manifest.json 记录本次 Lua 数据模块；旧的未列文件不会被服务端加载。
- 共享客户端 JSON 和内容身份输出到 server/build/generated。
- 每次结果保存在 export/导出结果.log，错误时可将日志交给开发人员。

导出检查
- 工具先转换全部根配置表，再用游戏实际使用的 Lua 配置模块校验单位、引用及玩法数值。
- 缺失工作簿、记录、字段、错误弹药、超重初装或非法几何会明确拒绝。
- 整数不可留空，公式不可导出；零是否允许由字段含义决定，不把空白自动解释成零。
- 以 # 开头的主键说明行跳过；真实数据行即使未被当前地图使用，也必须填完整字段。
- 校验失败保留上一份有效输出；可捕获的发布失败恢复原文件。
- 日志提示回滚失败时，请保留锁和恢复材料，交给开发人员处理。

生效方式
导出完成后重新构建脚本或 Bundle，服务端将由 Lua 加载这些配置并执行玩法规则。
本次不提供运行中热更新。客户端共享内容与同一份 Lua 规范内容保持一致。

旧草稿入口
开发可显式执行“导出配置.exe --draft”，此时按导出目标.txt 选择工作簿。
草稿只检查字段格式，不执行玩法关联校验，不进入生产运行时。
草稿输出到独立 server/build/draft-cfg，不覆盖正式 generated/cfg 内容。

开发验收参数
--check 完整检查但不发布配置；--no-ui 不显示窗口。二者仍写结果日志。
修改工具 Python 源码后应由开发重新打包 EXE；修改 Lua 校验逻辑则从项目直接读取。
